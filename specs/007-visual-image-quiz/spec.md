## Clarifications

### Session 2026-10-15
- Q: Каким способом пайплайн должен получать 10 изображений для викторины при выборе произвольной случайной темы? → A: Автоматический веб-поиск через существующий API (`/api/v1/quiz/search-image`) с обязательным шагом пользовательского предпросмотра и ручного утверждения (approval) картинок перед запуском рендера.
- Q: Как в левой лестнице уровней должен быть оформлен вопрос №10 («коммент-ловушка») относительно заголовков блоков? → A: Отдельный 4-й блок «Мастер / Финал» с собственным заголовком и пурпурно-розовой индикацией (`#EC4899`).
- Q: В каком объёме и в какой зоне экрана должны отображаться пословные караоке-субтитры в режиме visual_image_quiz? → A: Полные пословные караоке-субтитры для всех реплик диктора (интро-хук, вопросы, ответы, байты) в выделенной полосе `y: 1420..1500` строго над нижней безопасной зоной TikTok.
- Q: Должен ли таймер отсчёта запускаться одновременно с репликой вопроса диктора или только после её завершения? → A: Синхронный старт с быстрым таймером (1.5–2.0 сек) — картинка появляется, диктор сразу начинает реплику вопроса, и параллельно отрабатывает быстрый таймер для максимальной динамики.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Генерация сценария викторины для произвольной динамической темы (Priority: P1)

Создатель контента запускает генерацию викторины по любой произвольной теме (например, «Бренды одежды», «Спортивные автомобили», «Флаги стран мира», «Оружие из видеоигр», «Породы собак» и т.д.). Система через `@script-service` обращается к Gemini REST API, формирует сбалансированный сценарий из 10 вопросов с 4 градациями сложности (3 лёгких, 3 средних, 3 сложных, 1 мастер), генерирует интригующий хук-текст, реплики диктора и интерактивные призывы к действию (байты на комментарии и репост).

**Why this priority**: Фундаментальный уровень системы. Режим не должен быть ограничен только брендами — масштабируемость и ценность видеогенератора заключается в возможности создавать вирусные ролики по любой тематике по одному клику или CLI-команде.

**Independent Test**: Передача названия темы (или флага случайной темы) в `@script-service` генерирует полностью валидный датасет `VisualQuizDataset` по строгой Pydantic v2 схеме с 10 уникальными объектами, дифференцированными уровнями сложности и валидными URL/путями к изображениям.

**Acceptance Scenarios**:
1. **Given** произвольная тема (например, `"Ретро-автомобили"`), **When** запускается генерация сценария, **Then** формируется `VisualQuizDataset` ровно с 10 элементами, распределёнными по уровням (`easy`: 3, `medium`: 3, `hard`: 3, `master`: 1).
2. **Given** запрос без указания конкретной темы, **When** флаг рандомизации активен, **Then** система выбирает трендовую категорию и создаёт сбалансированный сценарий.
3. **Given** генерация сценария, **When** формируются реплики диктора, **Then** для вопроса №1 реплика не содержит фразы «Вопрос номер один» (сразу озвучивается вопрос: «Что это?», «Узнаешь эту эмблему?»), а для вопросов №2–№9 номер вопроса явно объявляется.
4. **Given** готовый сценарий с поисковыми запросами `image_query`, **When** пользователь переходит к этапу подготовки ассетов, **Then** система загружает превью кандидатов через `/api/v1/quiz/search-image`, позволяя пользователю подтвердить или заменить любое изображение перед запуском рендера.

### User Story 2 - Динамичный визуальный хук с быстрым флипом (Rapid Center Flip Hook 0:00–0:03.5s) (Priority: P1)

В первые 0:00–0:03.5 секунды видео зритель видит мощный визуальный хук: в единой центральной точке экрана (`x: 780, y: 450`, размер бокса `380x380 px`) на предельно высокой скорости (100–120 мс на кадр) циклически переключаются все 10 изображений из викторины, создавая эффект непрерывного калейдоскопа/флипбука. На фоне звучит энергичный голос диктора и сочный звуковой эффект быстрого перелистывания карточек (Rapid Flip SFX). Левая лестница уровней в этот момент скрыта, фокусируя всё внимание зрителя на центральном боксе.

**Why this priority**: Критический фактор удержания внимания (retention) в вертикальных соцсетях (TikTok / YouTube Shorts / Reels). Первые 3 секунды определяют, досмотрит ли зритель видео до конца.

**Independent Test**: Рендер тестовой композиции интро подтверждает точную смену текстур в фиксированном боксе каждые 100–120 мс на протяжении аудиореплики `hook_tts` со строгой синхронизацией SFX листания и отсутствием смещения координат бокса.

**Acceptance Scenarios**:
1. **Given** массив из 10 изображений и аудиодорожка `hook_tts` длительностью 3.2 секунды, **When** проигрывается сцена интро (0:00–0:03.5s), **Then** изображения сменяются ровно в координатах `x: 780, y: 450` с интервалом 100–120 мс, левая панель уровней остаётся невидимой, а в аудиомиксе воспроизводится Rapid Card Flip SFX.
2. **Given** завершение аудиореплики интро, **When** таймлайн достигает отметки окончания хука, **Then** циклический флип мгновенно прекращается и система бесшовно переходит к вопросу №1.

### User Story 3 - Последовательный геймплей с прогрессивной лестницей сложности и таймером (Priority: P1)

После окончания интро экран переходит в фазу викторины: слева отображается прогресс-лестница уровней с четырьмя цветовыми зонами («Лёгкий уровень» — зелёный, «Средний уровень» — жёлтый, «Эксперт» — красный, «Мастер / Финал» — пурпурный). Справа в том же центральном боксе появляется загаданный предмет с пружинящей анимацией масштабирования (`scale 0 -> 1.1 -> 1.0` за 200 мс). Одновременно диктор начинает реплику вопроса, и внизу запускается быстрый горизонтальный таймер (1.5–2.0 с) с плавной сменой цвета (зелёный -> жёлтый -> красный). По истечении таймера диктор озвучивает ответ, раздаётся звуковой сигнал «Ding!», и название предмета появляется на соответствующей строке левой лестницы.

**Why this priority**: Это основной игровой цикл (core loop) викторины, дающий зрителю понятные правила, азарт и визуальное вознаграждение за отгадывание.

**Independent Test**: Прогон вопросов Q1–Q9 подтверждает появление каждой картинки с пружинящей анимацией, корректную убывающую анимацию таймера за 1.5–2.0 секунды синхронно с речью, своевременное появление названия ответа в левой колонке только после ответа диктора и окрашивание уровней в соответствующие цвета.

**Acceptance Scenarios**:
1. **Given** начало вопроса Q1, **When** появляется карточка предмета, **Then** срабатывает анимация пружины (`scale 0 -> 1.1 -> 1.0` за 200 мс) и одновременно с речью диктора активируется горизонтальный таймер шириной 850 px на высоте `y: 1350`.
2. **Given** активный таймер вопроса, **When** проходит время таймера (1.5–2.0 с), **Then** полоса таймера плавно меняет цвет от `#22C55E` к `#FACC15` и затем к `#EF4444`, доходя до 0%.
3. **Given** завершение отсчёта времени, **When** диктор произносит ответ, **Then** звучит SFX колокольчика/подтверждения и в левой лестнице на соответствующей строке мгновенно появляется текстовый ответ с белым шрифтом и чёрной обводкой 4px.
4. **Given** переход между этапами сложности (например, с Q3 на Q4), **When** активируется новый блок, **Then** цвет текста и акцентов меняется с зелёного на жёлтый, а затем (Q7) на красный.

### User Story 4 - Интерактивные интерстишлы вовлечения и финальная коммент-ловушка (Priority: P2)

Для максимизации алгоритмического охвата платформами видео включает встроенные интерактивные триггеры:
1. После Q3 (вопрос лёгкого уровня) появляется анимированная плашка с призывом оставить комментарий («Зажми кнопку комментариев и отправь смайлик!») с поп-ап звуком.
2. После Q6 (вопрос среднего уровня) появляется анимированная стрелка репоста («Отправь другу!») со свистящим звуком перехода (Whoosh).
3. Вопрос Q10 («Мастер / Ловушка»): вопрос задаётся, таймер тикает, но правильный ответ намеренно НЕ озвучивается и НЕ пишется в лестнице. Вместо этого в строке 10 пишется «10. Пиши в коммы», диктор призывает зрителей писать свои догадки в комментариях, а на фоне звучит клиффхэнгер-дрожь барабанов.

**Why this priority**: Комментарии, репосты и сохранения являются ключевыми метриками виральности в рекомендательных алгоритмах TikTok, YouTube Shorts и Instagram Reels.

**Independent Test**: Рендер тестового видео подтверждает появление интерстишла комментариев ровно после Q3, стрелки репоста после Q6 и сокрытие ответа на Q10 с заменой текста на «10. Пиши в коммы» и призывом в аудио.

**Acceptance Scenarios**:
1. **Given** завершение ответа на Q3, **When** наступает межраундовая пауза, **Then** на экране появляется анимированная плашка комментариев на 1.5–2 секунды с соответствующей голосовой репликой и звуком поп-апа.
2. **Given** завершение ответа на Q6, **When** наступает межраундовая пауза, **Then** отображается динамическая стрелка репоста с озвучкой призыва переслать видео.
3. **Given** переход к вопросу Q10, **When** таймер истекает, **Then** правильный ответ не раскрывается, в левой колонке отображается текст «10. Пиши в коммы», диктор озвучивает интригующий призыв, звучит клиффхэнгер SFX, и ролик гармонично завершается.

### User Story 5 - Параметризация стилей, темпа речи и микширования звука (Priority: P3)

Создатель контента может через конфигурационный файл или аргументы CLI настраивать параметры генерации: множитель скорости диктора (`speech_rate` от 1.0x до 1.3x, по умолчанию 1.15x), длительность показа одного кадра в интро (от 80 до 150 мс, по умолчанию 120 мс), громкость звуковых эффектов и фоновой музыки, а также безопасные отступы для интерфейса TikTok/Reels.

**Why this priority**: Позволяет тонко адаптировать ролики под разные платформы, языки и вкусы аудитории без изменения исходного кода.

**Independent Test**: Изменение параметров в конфигурации влияет на скорость аудиодорожки, длительность таймлайна Remotion и итоговые уровни громкости аудиомикса.

**Acceptance Scenarios**:
1. **Given** параметр `rapid_flip_duration_ms = 100`, **When** рендерится интро, **Then** кадры сменяются каждые 100 мс (10 кадров в секунду).
2. **Given** параметр громкости фоновой музыки `-20 dB`, **When** выполняется сборка аудиомикса, **Then** FFmpeg выставляет уровень фонового трека строго на -20 dB относительно нормализованного голоса диктора (0 dB).

### Edge Cases

- **Сбой получения или повреждение одного из 10 изображений**: Если изображение для предмета не найдено локально или произошла ошибка загрузки, система должна заменять его на стилизованную нейтральную карточку-заглушку с силуэтом/вопросительным знаком и логировать предупреждение, не прерывая рендер ролика.
- **Длинные названия предметов в левой лестнице**: Название ответа содержит более 25 символов (например, «Mercedes-Benz 300SL Gullwing»). Текст должен автоматически сжиматься по ширине (`text-overflow: ellipsis` или адаптивный размер шрифта `clamp`), не выходя за пределы зоны `x: 480 px` и не перекрывая центральный бокс.
- **Нестандартные пропорции изображений**: Входные картинки имеют соотношение сторон отличное от 1:1 (например, 16:9 или 4:3). Внутри бокса `380x380 px` картинки должны центрироваться с `object-fit: contain` на прозрачном или тёмном матовом фоне без растяжения и деформации геометрии.
- **Длинный или медленный ответ диктора**: Длительность произнесения ответа превышает стандартный слот. Система `@audio-service` должна динамически адаптировать временные метки ключевых кадров в Remotion на основе реальной длительности аудиофайла (`AudioCueSheet`).
- **Сетевые сбои или rate-limit при обращении к Gemini REST API**: Система должна выполнять до 3 повторных попыток с экспоненциальной задержкой (backoff with jitter), а в случае фатального сбоя переключаться на локальный предопределённый шаблон сценария.
- **Наложение субтитров на системные элементы интерфейса**: Субтитры и плашки должны строго располагаться выше нижней безопасной зоны (минимум 400 px от нижнего края кадра, `y <= 1520 px`) и левее правой безопасной зоны (минимум 120 px от правого края под кнопки интерфейса).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система ДОЛЖНА поддерживать генерацию сценариев для произвольной темы викторины через `@script-service` с использованием Gemini REST API и валидацией выходных данных строгой схемой Pydantic v2 `VisualQuizDataset`.
- **FR-002**: Сценарий ДОЛЖЕН содержать ровно 10 вопросов с прогрессивной шкалой сложности: 3 лёгких (Q1–Q3), 3 средних (Q4–Q6), 3 сложных (Q7–Q9) и 1 мастер-вопрос (Q10).
- **FR-003**: В интро-фазе ролика (первые 3.0–3.5 секунды) система ДОЛЖНА воспроизводить циклический показ всех 10 картинок в едином координатном боксе `x: 780, y: 450` размером `380x380 px` с интервалом `100–120 мс` на кадр.
- **FR-004**: Во время интро-фазы левая панель уровней ДОЛЖНА быть скрыта, а в аудиодорожке ДОЛЖЕН воспроизводиться SFX быстрого листания карт (Rapid Flip) с громкостью `-4 dB` под интро-реплику диктора.
- **FR-005**: В игровой фазе (после интро) система ДОЛЖНА отображать левую панель уровней (`x: 80..480, y: 400..1250`) с 4 структурированными блоками и заголовками:
  - «Лёгкий уровень» (номера 1, 2, 3) — акцентный зелёный цвет `#22C55E`;
  - «Средний уровень» (номера 4, 5, 6) — акцентный жёлтый цвет `#FACC15`;
  - «Эксперт» (номера 7, 8, 9) — акцентный красный цвет `#EF4444`;
  - «Мастер / Финал» (номер 10) — акцентный пурпурно-розовый цвет `#EC4899`.
- **FR-006**: Текст правильного ответа напротив каждого номера в левой панели ДОЛЖЕН появляться только ПОСЛЕ истечения таймера ответа и начала озвучивания ответа диктором.
- **FR-007**: Для вопроса №1 реплика диктора ДОЛЖНА сразу называть сам вопрос («Что это?», «Угадай логотип!») без вводных слов «Вопрос номер один». Для вопросов с №2 по №9 номер вопроса ДОЛЖЕН явно объявляться в реплике.
- **FR-008**: При появлении каждого нового предмета в центральном боксе (`x: 780, y: 450`) система ДОЛЖНА воспроизводить пружинящую анимацию масштабирования (`scale 0 -> 1.1 -> 1.0` за 200 мс).
- **FR-009**: Система ДОЛЖНА отрисовывать горизонтальный индикатор таймера шириной 850 px на высоте `y: 1350`, запускаемый синхронно с появлением предмета и началом реплики диктора, плавно убывающий от 100% до 0% за 1.5–2.0 секунды (настраиваемый параметр, по умолчанию 2.0 с) с цветовым переходом: Зелёный (0–50%) -> Жёлтый (50–80%) -> Красный (80–100%). По истечении таймера сразу звучит подтверждающий сигнал (Ding) и диктор озвучивает ответ.
- **FR-010**: Система ДОЛЖНА интегрировать вовлекающие интерстишлы:
  - Байт на комментарии после вопроса Q3 (анимированная иконка комментариев + реплика призыва + поп-ап SFX);
  - Байт на репост после вопроса Q6 (анимированная стрелка + реплика призыва + Whoosh SFX).
- **FR-011**: Для вопроса №10 система ДОЛЖНА применять механику «коммент-ловушки»: правильный ответ НЕ выводится в левой панели (вместо него пишется «10. Пиши в коммы») и НЕ озвучивается диктором; диктор призывает зрителей писать свои догадки в комментариях, сопровождаемый клиффхэнгер-звуком.
- **FR-012**: Все визуальные элементы (тексты ответов, субтитры, таймер, плашки) ДОЛЖНЫ строго соблюдать безопасную зону вертикального формата 9:16 (1080x1920 px): не менее 400 px от нижнего края кадра (`y <= 1520`) и не менее 120 px от правого края кадра. Пословные караоке-субтитры для всех голосовых реплик диктора (интро, вопросы, ответы, призывы к действию) ДОЛЖНЫ отображаться в выделенной полосе `y: 1420..1500` непосредственно под горизонтальным таймером.
- **FR-013**: Синтез речи диктора ДОЛЖЕН выполняться через `@audio-service` с использованием нейросетевых голосов Edge-TTS с ускорением речи `1.15x` и нормализацией громкости `0 dB`.
- **FR-014**: Звуковой микс ДОЛЖЕН объединять: голос диктора (`0 dB`), SFX листания карт (`-4 dB`), тиканье таймера (`-6 dB`), сигнал правильного ответа (`-4 dB`), фоновый ритмичный бит (`-18 dB`).
- **FR-015**: Отрисовка видео ДОЛЖНА выполняться на базе декларативного движка Remotion (React, TypeScript, Tailwind CSS) в разрешении 1080x1920 с частотой 60 кадров в секунду без мутации шаблонов через входные пропсы `VisualImageQuizProps`.
- **FR-016**: Система ДОЛЖНА автоматически формировать поисковые запросы (`image_query`) для каждого из 10 предметов и задействовать поисковый сервис `/api/v1/quiz/search-image` с предоставлением пользователю интерактивного интерфейса для предпросмотра, выбора или ручной замены картинок до запуска рендера Remotion.

### Key Entities

- **`VisualQuizItem`**: Спецификация одного вопроса викторины. Содержит:
  - `id`: порядковый номер (1..10);
  - `difficulty`: уровень сложности (`easy`, `medium`, `hard`, `master`);
  - `image_query`: текстовый поисковый запрос для автоподбора картинки;
  - `image_url`: прямой URL выбранного изображения (или null до выбора);
  - `image_path`: локальный путь к скачанному и кэшированному файлу изображения;
  - `is_approved`: флаг подтверждения пользователем;
  - `answer_text`: краткое текстовое название ответа для левой панели;
  - `prompt_tts`: реплика диктора с вопросом;
  - `answer_tts`: реплика диктора с правильным ответом (для Q10 — призыв писать в комментарии).
- **`VisualQuizInterstitial`**: Описание промежуточной вовлекающей вставки. Содержит:
  - `after_question`: номер вопроса, после которого показывается вставка (3 или 6);
  - `type`: тип активности (`comment_bait`, `share_bait`);
  - `tts_text`: голосовой призыв диктора;
  - `duration_sec`: длительность вставки (1.5–2.0 сек).
- **`VisualQuizDataset`**: Полный сценарий викторины. Содержит:
  - `mode`: строковый идентификатор `"visual_image_quiz"`;
  - `theme`: текстовое название темы (например, «Суперкары мира»);
  - `hook_tts`: интро-реплика диктора;
  - `rapid_flip_duration_ms`: интервал смены картинок в интро (100–120 мс);
  - `items`: список ровно из 10 объектов `VisualQuizItem`;
  - `interstitials`: список вставок `VisualQuizInterstitial`.
- **`VisualQuizRenderProps`**: Структура входных данных для Remotion-композиции. Содержит:
  - `dataset`: валидированный `VisualQuizDataset`;
  - `audio_cue_sheet`: временные метки каждого фрагмента озвучки, пауз и звуковых эффектов;
  - `total_duration_frames`: общая длительность композиции в кадрах при 60 fps;
  - `audio_mix_path`: путь к предварительно сведённому мастер-аудиофайлу.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Генерация полного структурированного сценария `VisualQuizDataset` через Gemini REST API для любой переданной темы выполняется и валидируется Pydantic v2 менее чем за 5.0 секунд при стабильном сетевом подключении.
- **SC-002**: Точность переключения кадров в центральном боксе интро составляет ровно 100–120 мс на кадр (с точностью до 1 кадра при 60 fps) без джиттера координат (`x: 780, y: 450`).
- **SC-003**: 100% текстовых элементов, плашек и субтитров гарантированно укладываются в безопасную зону 1080x1920 (отступ снизу >= 400 px, отступ справа >= 120 px), подтверждаясь автоматическим тестом проверки верстки.
- **SC-004**: Суммарная длительность готового видеоролика укладывается в целевое окно 45–55 секунд с идеальной синхронизацией аудиосигналов (SFX звонка ответа совпадает с моментом появления текста в пределах 50 мс).
- **SC-005**: Декларативный рендер Remotion 1080x1920 60fps завершается без переполнения памяти (OOM) и утечек ресурсов, а все временные файлы детерминированно очищаются по завершении.

## Assumptions

- **Доступность изображений**: Изображения для предметов генерируются, загружаются через серч-пайплайн или берутся из локального банка ассетов `assets/quizzes/<theme>/` перед запуском финального рендера Remotion.
- **Поддержка платформ**: Основные целевые платформы — мобильные клиенты TikTok, YouTube Shorts и Instagram Reels с вертикальным соотношением 9:16.
- **Инфраструктура рендера**: На рабочей станции установлены Node.js 18+, Remotion CLI и FFmpeg с аппаратным ускорением (NVENC/CPU).
- **Синтез речи**: По умолчанию используется `edge-tts` с голосом `ru-RU-DmitryNeural` (или кастомная RVC-модель при активации модуля `006-custom-voice-rvc`).
- **Язык контента**: Базовый язык озвучки и интерфейса — русский (ru-RU), с возможностью интернационализации через конфигурацию.
