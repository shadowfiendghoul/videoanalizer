## 1. Архитектура Remotion-композиции для Visual Image Quiz

### Проблема
Режим `visual_image_quiz` принципиально отличается от классической текстовой викторины с 4 вариантами ответов:
- В первые 3–3.5 сек в единой координатной точке экрана (`x: 780, y: 450`, бокс `380x380 px`) происходит циклический быстрый флип 10 картинок со скоростью 100–120 мс на кадр.
- Слева расположена фиксированная 4-уровневая лестница сложности («Лёгкий», «Средний», «Эксперт», «Мастер / Финал»).
- На вопрос №1 реплика начинается сразу без префикса «Вопрос номер один».
- Картинка появляется с пружинной анимацией (`scale 0 -> 1.1 -> 1.0` за 200 мс).
- Таймер 1.5–2.0 сек работает синхронно с речью вопроса.
- Вопрос №10 — коммент-ловушка со скрытым ответом.

### Решение
Создать отдельную Remotion-композицию `VisualImageQuiz` в `templates/quiz-remotion/src/VisualImageQuiz.tsx` и зарегистрировать ее в `Root.tsx`:
1. **Координатная сетка (1080x1920)**:
   - Бокс загадки: `x: 780, y: 450` (центральное позиционирование правой части экрана: `left: 590px, top: 260px`, `width: 380px, height: 380px`).
   - Левая лестница уровней: `left: 80px, top: 380px, width: 440px, height: 860px`.
   - Горизонтальный таймер: `left: 115px, top: 1350px, width: 850px, height: 18px`.
   - Караоке-субтитры: `top: 1420px..1500px, width: 920px`, выровненные по центру.
   - Безопасная зона: нижняя граница контента не превышает `y: 1520px` (отступ снизу 400px), правая граница не превышает `x: 960px` (отступ справа 120px).
2. **Анимации Remotion**:
   - `RapidCenterFlip.tsx`: При `frame < hookEndFrame` вычисляет активный индекс `Math.floor(frame / framesPerFlip) % 10`, где `framesPerFlip = Math.round(fps * (flipMs / 1000))` (~7 кадров при 120 мс и 60 fps). Смена происходит мгновенно без смещения координат.
   - `SpringImageCard.tsx`: Использует `spring({ frame: localFrame, fps, config: { damping: 12, stiffness: 200 } })` для появления карточки (`scale 0 -> 1.1 -> 1.0` за ~12 кадров / 200 мс).
   - `SyncHorizontalTimer.tsx`: Линейно убывающая ширина с интерполяцией `interpolateColors` (`#22C55E` -> `#FACC15` -> `#EF4444`).
   - `QuestionLadder.tsx`: 4 блока с заголовками. Текст правильного ответа скрыт до наступления кадра `reveal_frame` для каждого вопроса. Для Q10 всегда рендерится «10. Пиши в коммы» пурпурным цветом.
   - `EngagementOverlay.tsx`: Всплывающие плашки стикера комментариев (после Q3) и стрелки репоста (после Q6).

### Отвергнутые альтернативы
- *Модификация существующего `QuizChallenge.tsx`*: Отвергнуто. Классическая викторина использует 4 кнопки вариантов ответов и абсолютно другую компоновку экрана. Смешивание логики приведет к регрессиям и нарушению принципа единственной ответственности.

## 2. Генерация сценария для произвольных тем через Gemini REST API

### Проблема
Пользователь подчеркнул: темы должны быть произвольными и случайными (автомобили, флаги, породы собак, персонажи аниме, оружие, ретро-игры и т.д.), а не только бренды одежды.

### Решение
Расширить `@script-service` (`videoanalizer/quiz/script_service.py`):
1. **Промпт генерации сценария (`VISUAL_QUIZ_PROMPT_TEMPLATE`)**:
   - Принимает `theme: Optional[str] = None`. Если тема не задана, Gemini выбирает одну из 50 вирусных визуальных категорий.
   - Требует ровно 10 узнаваемых визуальных объектов с нарастающей сложностью:
     - 3 лёгких (`easy`): всемирно известные силуэты/логотипы/предметы;
     - 3 средних (`medium`): известные любителям темы;
     - 3 сложных (`hard`): требующие экспертных знаний;
     - 1 мастер/ловушка (`master`): редкий или неоднозначный предмет, вызывающий споры.
   - Формирует поисковый запрос `image_query` для каждого предмета (например, `"nike logo transparent png"`, `"ferrari f40 side view isolated"`).
   - Генерирует лаконичные реплики: для Q1 реплика сразу содержит вопрос без префикса номера; для Q10 реплика ответа содержит призыв писать догадку в комментарии.
2. **Строгая Pydantic v2 валидация**:
   - `VisualQuizDataset` гарантирует наличие ровно 10 элементов, корректных интерстишлов и валидных полей.

## 3. Подбор картинок и Human-in-the-Loop Approval

### Проблема
Автоматический поиск в сети может выдавать картинки с низким разрешением, неподходящим фоном или водяными знаками. Пользователь запросил возможность ручного утверждения (approval) найденных картинок, аналогично существующей системе проекта.

### Решение
1. **Интеграция с `/api/v1/quiz/search-image`**:
   - При генерации сценария для каждого вопроса автоматически выполняется фоновый запрос к существующему сервису поиска картинок (DuckDuckGo Search) по полю `image_query`.
   - Система собирает список кандидатов (до 4 вариантов на предмет) и выставляет первый вариант как `image_url` по умолчанию со статусом `is_approved = False`.
2. **Интерфейс модерации в веб-UI (`quiz.html`)**:
   - В мастере создания викторины при выборе режима `visual_image_quiz` отображается компактная плитка из 10 карточек.
   - Пользователь видит превью выбранной картинки, может нажать «Сменить» (выпадают альтернативные превью) или загрузить свой локальный файл.
   - Кнопка «Утвердить всё» или поштучные галочки подтверждения.
3. **Автономный CLI-режим**:
   - При запуске через Python CLI или скрипт пакетной генерации с флагом `--auto-approve` система автоматически берет первого валидного кандидата, скачивает и кэширует его в `assets/quizzes/<theme_slug>/`.

## 4. Сборка аудиоряда и синхронизация таймингов (`@audio-service`)

### Проблема
Таймер длится 1.5–2.0 с и должен работать синхронно с репликой вопроса диктора, после чего звучит сигнал ответа (Ding) и диктор озвучивает правильный ответ. Также в интро звучит Rapid Flip SFX, после Q3 — Pop SFX, после Q6 — Whoosh SFX, на Q10 — барабанная дробь.

### Решение
1. **Синтез речи (Edge-TTS 1.15x)**:
   - Синтезируются: `hook_tts`, 10 реплик вопросов, 9 реплик ответов, 1 реплика финала Q10, 2 интерстишла.
   - Для всех реплик извлекаются пословные временные метки `WordBoundary` для формирования караоке-субтитров.
2. **Формирование `AudioCueSheet`**:
   - Вычисляются точные абсолютные смещения по времени (секунды и кадры при 60 fps).
   - Таймер вопроса стартует в момент начала реплики вопроса. Длительность таймера фиксируется (например, 2.0 сек).
   - По истечении таймера планируется SFX `ding.wav` и сразу за ним — аудио реплики ответа.
   - В интро на протяжении всей длительности `hook_tts` накладывается циклический звук `card_flip_rapid.wav` с громкостью `-4 dB`.
3. **Микширование в FFmpeg**:
   - Все фрагменты сводятся в единый мастер-аудиофайл `audio_mix.wav` с нормализацией голоса диктора до `0 dB`, звуков эффектов до `-4..-6 dB`, фоновой музыки до `-18 dB`.
